# Objective

After the user merges the PR from T3.9, tag `v0.3.0` on `main` of the new `halcytone` repo, then archive the two predecessor repos on GitHub with README pointer commits. Existing tags on `halcytone-contracts` are preserved.

**Precondition:** the user has merged T3.9's PR into `main` of the new `halcytone` repo. Manual handoff — engage/start-task can't drive this step.

# Implementation Plan

1. Tag new release:
   ```bash
   cd /home/kmasty/projects/halcytone
   git checkout main && git pull --ff-only
   git tag -a v0.3.0 -m "halcytone v0.3.0 — monorepo consolidation"
   git push origin v0.3.0
   ```
2. halcytone-contracts archive:
   ```bash
   cd /home/kmasty/projects/halcytone-contracts
   git checkout main && git pull --ff-only
   # Prepend "This repo is archived. Continuing work at fivedollarfridays/halcytone." to README.md.
   git add README.md
   git commit -m "docs: archive pointer — continuing work at fivedollarfridays/halcytone"
   git push origin main
   gh repo edit fivedollarfridays/halcytone-contracts --archived
   ```
3. halcytone-core archive (same pattern):
   ```bash
   cd /home/kmasty/projects/halcytone-core
   git checkout main && git pull --ff-only
   # Prepend archive notice to README.md.
   git add README.md && git commit -m "docs: archive pointer — continuing work at fivedollarfridays/halcytone"
   git push origin main
   gh repo edit fivedollarfridays/halcytone-core --archived
   ```
4. Verify halcytone-contracts tags still listed: `gh api repos/fivedollarfridays/halcytone-contracts/tags`.
